Adding the source

<?xml version="1.0" encoding="utf-8"?>
<configuration>
  <packageSources>
    <add key="acemq" value="https://acemq.org/nuget/index.json" />
  </packageSources>
</configuration>

Save that as nuget.config beside your solution, then reference packages as usual with dotnet add package.

What a static feed can and cannot do

NuGet's v3 protocol defines four required resources, and three of them need a server that answers queries or accepts uploads. A static host can serve only the flat container. Everything below was tested rather than assumed.

OperationResult
dotnet restore, dotnet buildworks
dotnet add package with a versionworks
Floating versions such as 1.*works
dotnet package searchno search resource
Browsing in Visual Studio's package managerneeds search
dotnet nuget pushpublishing is a commit

A project that names its packages and versions restores and builds against this feed exactly as it would against nuget.org. What it cannot do is discover packages here — the same trade the Maven repository makes.
